# Work With Google Report Evidence

Use the same evidence rules for an authorized connected report and an adequate export the host can read. Identify the source, property, reporting period, search or acquisition scope, filters, dimensions, metrics, aggregation and known limits. Inspect the observations before judging whether they answer the question. A ready method and a visible filename establish only prerequisites for evidence review.

## Choose the Source

Use adequate supplied evidence without requiring a connection or an upgrade. If a necessary observation is missing, request the smallest readable addition or use an independently authorized connection for the missing evidence. For a mixed route, keep source provenance and confirm comparable scope before combining observations.

Discover the current operation for any connected acquisition and confirm access to the selected property or stream. Obtain its current input-specific quote and follow the user's authorization before chargeable calls. A plan with zero default calls leaves the cost of optional acquisition open. Method availability, report sufficiency and the cost of connected acquisition each depend on their own evidence.

For client-side analysis, give the user the [Google report export and upload guide](https://github.com/TechSpokes/seo-agent-tools/blob/main/docs/google-data-exports.md). If the host cannot read the attachment, ask for a supported format or the necessary rows and report context. If only part of the evidence is usable, answer the supported narrower question and name the smallest additional report or fields needed for the requested conclusion.

## Keep Sources Comparable

Search Console clicks, impressions, click-through rate and average position describe Google search performance. Keep property and page aggregations and returned query coverage distinct. Keep CTR with its clicks and impressions and average position with its reported aggregation.

GA4 reports sessions, engagement and recorded events at defined property, acquisition and reporting scopes. A current setting establishes what is enabled at observation time. Ordered user progression requires ordered evidence. Separately reported step totals describe independent observations. A recorded event establishes a business outcome only when appropriate outcome evidence supports that interpretation. Use the property timezone when reported and leave it unknown otherwise. Distinguish all Organic Search from the Google organic slice and leave query-level conversions unknown when the source has only aggregates.

## Reconcile Search Console Comparison Pages

1. Combine only responses with compatible property, ordered dimensions, filters, search surface, aggregation and definitions of the compared reporting periods. Check metric definitions before comparing values. Retain the source scope and observation time of each response.
2. Accumulate actual returned observations by the exact full dimension tuple and by period. For a page-and-query report, retain the full returned page and query values together. Keep observed zeros and carry forward previously returned values when another response marks the same period `not_returned`. Keep unavailable values and ambiguous export placeholders unknown.
3. Count each exact tuple once. Repeated identical observations for a tuple and period contribute once. If comparable responses give conflicting values for the same tuple and period, retain the competing observations with their provenance and limit the affected comparison until reconciled.
4. Calculate changes and report the matched and unresolved coverage after accumulation. If a value is still unknown on either side, leave the affected change unknown. Use compatible denominators for derived rates and retain reported averages at their source grain.
5. Follow each reporting period's own continuation only while it can change the scoped decision. A completed continuation describes the rows made available for that report within its scope and does not establish exhaustive coverage of search activity.

## Follow Up on a Decision

Route a single authorized report, setting or URL observation directly if it is sufficient. Use a recipe for dependent investigation or prioritization. Treat sitemap submission, Google's indexed-version evidence and current public page behavior as separate observations with dates and scope. Evidence from a URL sample supports conclusions about that sample.

Before routing a performance finding into a page refresh, recheck current technical state and target suitability. Carry the exact target, decisive values, reporting periods, source and uncertainty into the [implementation handoff](implementation-handoff.md) when a different capability owns a supported action. A decision to preserve the page can complete with the reasons and a useful follow-up condition.
