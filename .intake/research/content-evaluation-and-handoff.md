# Content Evaluation And Handoff

## Evaluation Goal

Determine whether the existing content is adequate for the observed SEO purpose, whether intervention is justified, and what kind of intervention is supported.

The output is a diagnosis and implementation contract. It is not rewritten content.

## Required Decision Sequence

1. Identify the page's intended business job, user, query, and page role.
2. Validate that demand and observed search intent support that role.
3. Compare the page type with the dominant SERP page type.
4. Evaluate observable content against user questions, proof needs, structure, and next action.
5. Evaluate technical, authority, cannibalization, and operational alternatives when evidence permits.
6. Locate the earliest supported failure layer.
7. Select page strategy and recommendation disposition separately.
8. Produce preservation constraints, intervention requirements, unresolved inputs, and verification.

## Diagnostic Layers

| Layer             | Evidence questions                                                                                                               | Typical result                                        |
| ---               | ---                                                                                                                              | ---                                                   |
| Strategic         | Does this page belong in a coherent site and intent structure? Is another page the correct target?                               | Create, consolidate, preserve, or revise architecture |
| Demand and intent | Does a real query exist and what task and page type dominate its SERP?                                                           | Proceed, change target, defer, or reject              |
| Planning          | Are intended user, page job, target query, page type, proof, and onward path specific and consistent?                            | Refresh brief or request missing owner input          |
| Content           | Does the page answer the task, cover buyer questions, preserve trust, support claims, and make the next action clear?            | Preserve or refresh with explicit gaps                |
| Technical         | Is discovery, crawlability, metadata, canonicalization, rendering, performance, structured data, or linking the supported cause? | Technical fix or further technical evidence           |
| Authority         | Does available evidence indicate that competition or backlink authority limits the opportunity more than content?                | Authority work, narrower target, or defer             |
| Operational       | Do first-party indexing, impressions, CTR, conversion, or trend signals identify the failure?                                    | Measured intervention or unknown without data         |

## Page Strategy

Use one page strategy:

- `create`: A coherent opportunity exists and no adequate current page serves it.
- `refresh`: The existing page is the right target but has evidence-backed deficiencies.
- `consolidate`: Multiple pages divide one intent or create avoidable overlap.
- `preserve`: The existing page satisfies the supported requirements or change risk exceeds supported benefit.

Use one disposition separately:

- `proceed`: Evidence supports action now.
- `conditional`: Action is supported after named inputs, proof, approval, or constraints are resolved.
- `defer`: Revisit after a named evidence or timing condition.
- `reject`: The proposed target or intervention conflicts with the evidence.

## Evidence Gates

Do not make a content-quality conclusion from a single aggregate score. Inspect the underlying evidence and compare it with the target intent and page role.

Do not infer first-party performance from estimated public metrics. A page can be evaluated for observable fit without claiming how it converts.

Do not request invented proof. Record proof gaps as owner inputs.

Do not recommend multiple broad interventions when one earlier failure explains the observed symptoms.

## Implementation Handoff

A content implementation handoff should contain only fields relevant to the decision:

- Source recipe and analysis identity.
- Target URL or proposed page target.
- Page strategy and disposition.
- Primary query and close variants.
- Observed intent, page type, audience or journey state, and confidence.
- Named evidence and competing-page observations.
- Preserved strengths and non-negotiable constraints.
- Required changes, removals, and additions stated as outcomes.
- Buyer questions and proof requirements.
- Internal-link requirements justified by the reader's next step.
- Missing owner inputs and unsupported claims to avoid.
- Acceptance criteria and verification plan.

The handoff must leave wording and craft to the downstream implementation agent unless the user explicitly invokes another writing capability.

## Result Audit

When reviewing completed content, compare it with the handoff rather than starting a new taste-based critique. Verify each preservation constraint, required change, buyer question, proof input, internal link, claim limit, and acceptance criterion.

Return pass, partial, or fail with evidence. Do not rewrite the work during the audit.
